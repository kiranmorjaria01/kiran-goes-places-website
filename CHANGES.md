# Changes

Tracks what shipped per phase of the GEO/AEO brief. One entry per phase, most recent first.

## Phase 1: crawl and index foundation (2026-08-18)

- **robots.txt** — replaced the two-line wildcard file with explicit per-bot `Allow` rules for every crawler named in the brief (GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-User, Claude-SearchBot, PerplexityBot, Perplexity-User, Google-Extended, Bingbot, Applebot-Extended, CCBot), plus the original wildcard block. **Note on the training-only crawlers** (GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, CCBot double up as training crawlers, not just retrieval): per the brief's instruction to default to allowing them while flagging the tradeoff, I've allowed all of them. The tradeoff: allowing them means your writing can be used to train future model weights, with no way to opt out selectively once it's ingested; blocking them would not affect retrieval-time citation (the stated goal of this whole brief) since ChatGPT-User/Claude-User/PerplexityBot etc. are separate, already-allowed crawlers for that. If you'd rather block the training-only set, that's a one-line change per bot (`Disallow: /` under its own `User-agent` block) and I can do it on your say-so.
- **sitemap.xml** — regenerated. Fixed the one gap found in the audit (the Suzuka F1 post was missing entirely) and added `lastmod` to the homepage and `/blog/` listing page, which previously had none. All 52 URLs (homepage, blog listing, 50 posts) now carry a `lastmod` of 2026-08-18, reflecting today's edits — every one of those pages had its `<title>`/meta description touched in this phase, so that date is accurate, not placeholder.
- **RSS feed** — added `blog/feed.xml` (RSS 2.0, 50 items, newest first), auto-discoverable via a `<link rel="alternate" type="application/rss+xml">` tag added to both `index.html` and `blog/index.html`. Feed item titles/descriptions reuse each post's existing `og:title`/`og:description` (the fuller, narrative versions), not the newly shortened SEO title/description, so the feed keeps the site's voice intact.
- **Canonical tags** — verified programmatically: all 52 pages already had a correct, unique `<link rel="canonical">`. No changes needed here.
- **Titles and meta descriptions** — rewrote the `<title>` and meta description on all 50 blog posts plus the homepage so every one is unique and sits under the 60/155 character limits. Verified programmatically: no duplicates, nothing over budget. Two decisions worth flagging:
  - Blog post `<title>` tags no longer carry the `| Kiran Goes Places` suffix. Budget with the suffix included was roughly 39 usable characters, too tight to keep any of the voice-driven titles legible. The brand is still carried by the URL, the nav logo, `og:site_name`, and (once Phase 2 lands) the `Organization`/`Person` JSON-LD. The homepage keeps a shortened suffix since it's the one page where that matters most.
  - Only the `<title>` tag and the `meta description` tag were changed. The on-page `<h1>` article title, subheading, body copy, `og:title`, `og:description`, `twitter:title` and the JSON-LD `headline` were all left exactly as they were. This was a deliberate scope decision, not an oversight: the brief's 60/155 character limits apply to what search/AI engines display for a result snippet, not to the page's actual content or its social-share preview, and rewriting the H1/body text was explicitly out of scope ("do not restyle or redesign anything," and Phase 4 owns on-page structure). It does mean each post now carries three slightly different title strings (SERP `<title>`, social `og:title`, on-page `<h1>`) — that's standard practice, not a bug, but flagging it since it wasn't true before.
  - All new title/description text was written by condensing the existing hand-written title and description for that post — no new facts, places, prices or times were introduced anywhere.
- **meta keywords tag** — removed. It only existed on the homepage (no blog post had one), so this was a single-line deletion.
- **JavaScript-disabled rendering** — confirmed already true (see AUDIT.md item 6), no changes needed. Every post's full text and images are static HTML; only the video-embed click-to-play swap, nav animation, and contact form depend on JS.

### Not touched in this phase
Everything else in the brief (JSON-LD, hub pages, "the short version" blocks, internal linking, transcripts, author bylines) is Phase 2 onward and hasn't been started.
